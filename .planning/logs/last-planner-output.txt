## Analysis

### What Already Exists

**Worker (apps/worker/):**
- `main.py` — FastAPI admin API on port 8001 with health, job CRUD endpoints
- `admin.py` — Admin route definitions (health, list jobs, get job, retry job)
- `db.py` — `get_session()` for gts_core only (single database)
- `broker.py` — TaskIQ Redis broker setup
- `config.py` — Worker configuration (DATABASE_URL for gts_core, REDIS_URL)
- `tasks.py` — TaskIQ task definitions
- `lock.py` — Redis distributed lock
- `health.py` — Health check utilities
- `jobs/` — handlers.py, registry.py, enqueue.py, heartbeat.py, retry.py, source_sync.py (stub)
- `consumers/` — `__init__.py` (empty), `gear_sync.py` (stub/placeholder)
- `services/` — `admin_service.py`, `gear_mapper.py` (stub)

**Scheduler (apps/scheduler/):**
- `main.py` — Scheduler entry point
- `config.py` — Configuration
- `broker.py` — TaskIQ broker
- `schedules/` — `jobs.py` (stale monitor, retries, heartbeat), `maintenance.py`, `auth.py` (stub)

**Source T3K (sources/t3k/):**
- Domain models: `models.py` (T3KPack, T3KModel, T3KCreator), `staging.py`, `checkpoints.py`
- Adapters: API client with rate limiter + circuit breaker, OAuth, auth
- Outbound: `pgmq_publisher.py`, `queue_publisher.py`, `sync_record_mapper.py`
- Services: `sync_service.py` (partial), `model_downloader.py` (stub), `oauth_manager.py`
- Migrations: `001_initial_staging_tables.py`, `002_add_pgmq_queue.py`

**Core:**
- `records/gear_sync.py` — GearSyncRecord Pydantic model
- Domain entities: Gear, GearModel, GearSource, Job with types

**Docker:**
- Worker command runs TaskIQ only, not admin API + pgmq consumer
- Single database connection for worker (gts_core only)
- pgmq extension initialized in `init-pgmq.sql` on `gts_t3k_source`
