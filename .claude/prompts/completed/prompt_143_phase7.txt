## Phase 7: Clean up remaining HTMX fragment endpoints

### Current state of html.py

| Function | Current URL | Method |
|----------|-------------|--------|
| `gear_model_toggle` | `POST /api/html/library/gear/{model_id}/toggle` | Toggle gear save/unsave |
| `gear_models_bulk_toggle` | `POST /api/html/library/gear/models/bulk-toggle` | Bulk toggle |
| `library_track_toggle_public` | `POST /api/html/library/tracks/{track_id}/toggle-public` | Track visibility |

| `job_status_fragment` | `GET /api/html/jobs/{job_id}` | Job status polling |

### Plan

Move endpoints to entity-namespaced URLs:

**Library gear toggles → keep under `/api/html/` (they return HTML fragments):**
- `POST /api/html/library/gear/{model_id}/toggle` — no change needed
- `POST /api/html/library/gear/models/bulk-toggle` — no change needed

**Library track actions → keep under `/api/html/`:**
- `POST /api/html/library/tracks/{track_id}/toggle-public` — no change needed
- `POST /api/html/library/tracks/{track_id}/save` — no change needed

**Shootout wizard → keep under `/api/html/`:**
- `GET /api/html/shootout-create/chains` — no change needed
- `GET /api/html/shootout-create/ditracks` — no change needed
- `POST /api/html/shootout-create` — no change needed

**Shootout comments → keep under `/api/html/`:**
- `GET /api/html/shootouts/{id}/comments` — no change needed

**Job status → keep under `/api/html/`:**
- `GET /api/html/jobs/{job_id}` — no change needed

**Key question:** The plan says to move some endpoints to entity-namespaced URLs like `POST /library/gear/{model_id}/toggle`. But these are HTMX endpoints returning HTML fragments — they belong under `/api/html/` which is where they already are post-Phase 5. The current URLs are already entity-namespaced within the `/api/html/` prefix.

**What Phase 7 actually needs to do:**
1. Verify all remaining html.py endpoints have frontend callers (grep templates for each URL)
2. Verify the `shootout_comments_fragment` endpoint actually works (it was flagged as "not wired" in Phase 2 but kept)
3. Consider if html.py should be merged into pages.py (one router for all HTML) or kept separate
