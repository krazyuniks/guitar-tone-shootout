## Objective

Create a custom exception hierarchy for the GTS webapp. All application-level errors should raise domain exceptions that map to HTTP status codes. This replaces scattered `HTTPException` raises with structured, consistent error handling.

## Acceptance Criteria

- [ ] `AppException` base class with `status_code`, `error_code`, `message`, `details` attributes
- [ ] `NotFoundError(AppException)` — 404
- [ ] `AuthorizationError(AppException)` — 403
- [ ] `ConflictError(AppException)` — 409
- [ ] `BadRequestError(AppException)` — 400
- [ ] `ValidationError(AppException)` — 422
- [ ] Each exception serialises to `{"error_code": "...", "message": "...", "details": {...}}`
- [ ] No framework dependencies in the exception module itself
- [ ] `just check` passes
