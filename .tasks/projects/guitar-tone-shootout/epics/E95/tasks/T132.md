## Objective

Create Preset CRUD API endpoints. `PresetService` already exists. Presets store reusable signal chain parameter configurations. A `PresetProcessor` validates chain parameters against block type definitions.

## Acceptance Criteria

- [ ] `GET /api/v1/presets` — list current user's presets
- [ ] `POST /api/v1/presets` — create preset with name, description, chain parameters
- [ ] `GET /api/v1/presets/{id}` — get preset detail (ownership check)
- [ ] `PUT /api/v1/presets/{id}` — update preset (ownership check)
- [ ] `DELETE /api/v1/presets/{id}` — delete preset (ownership check)
- [ ] `PresetProcessor` validates chain parameters against block type definitions on create/update
- [ ] Invalid parameters rejected with ValidationError
- [ ] Pydantic schemas for request/response
- [ ] All endpoints require `CurrentUser` authentication
- [ ] `just check` passes
