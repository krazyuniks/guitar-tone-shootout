## Objective

9 of the 11 admin endpoints return hardcoded defaults with TODO comments (lines ~440-630 in `admin.py`). Replace all stubs with real implementations that query actual infrastructure: Redis for lock state, PostgreSQL for sync checkpoints and job records, pgmq for queue depths, and TaskIQ for job dispatch.

## Acceptance Criteria

- [ ] `GET .../sync/status` queries `SyncCheckpoint` table + Redis lock state, returns real sync state
- [ ] `POST .../sync` dispatches `handle_source_sync` TaskIQ job, returns 202 Accepted
- [ ] `GET .../sync/stats` queries `SyncCheckpoint.total_synced` + pgmq queue depths from real DB
- [ ] `GET .../sync/lag` calculates real seconds since `SyncCheckpoint.last_synced_at`
- [ ] `GET .../errors/summary` queries failed Job records in last 24h from gts_core
- [ ] `GET .../auth/status` queries `oauth_tokens` table in gts_t3k_source for real token status
- [ ] `POST .../sync/unlock` deletes Redis key `t3k:sync:lock`, returns 200
- [ ] `POST .../scheduler/unlock` deletes Redis key `scheduler:lock`, returns 200
- [ ] `POST /enqueue` dispatches job to TaskIQ broker, returns job detail
- [ ] No endpoint returns hardcoded/stubbed data — all query real infrastructure
