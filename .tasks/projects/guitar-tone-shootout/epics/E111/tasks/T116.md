## Objective

Write real integration tests for the T3K catalog sync loop. The implementation exists and is wired — tests must verify observable product behaviour using real database sessions and real T3K API calls with auth tokens.

## Acceptance Criteria (Observable Product Behaviour)

- [ ] After `run_catalog_sync(max_iterations=1)` with real T3K API, `SyncCheckpoint.last_record_id` in DB has advanced
- [ ] After sync, `SELECT count(*) FROM t3k_pack_staging` returns > 0 (real T3K data)
- [ ] After sync, `SELECT count(*) FROM t3k_model_staging` returns > 0 (real T3K data)
- [ ] `GearSyncPublisher` receives real `GearSyncRecord` objects from staged data
- [ ] When seeding records synced within 7 days, those records are skipped (verified via DB read)
- [ ] When checkpoint is >30 days old, it resets (verified via DB read)
- [ ] Each batch commits checkpoint (verified via DB read between batches)

## Test Approach

- **Location:** `tests/integration/t3k/test_catalog_sync.py`
- **DB:** Real PostgreSQL (gts_t3k_source) via Docker — staging tables are real
- **T3K API:** Real T3K API calls using auth tokens from `.gts-auth.json`
- **Publisher:** Simple callable that collects args (outbound adapter to pgmq)
- **Fixtures:** Create `tests/integration/t3k/conftest.py` with T3K DB session fixtures

**Testing policy:** No mocking. Tests use real services — real databases, real Redis, real T3K API, real pgmq. The `test_quality_check.py` gate bans all `unittest.mock` imports with zero exceptions.
