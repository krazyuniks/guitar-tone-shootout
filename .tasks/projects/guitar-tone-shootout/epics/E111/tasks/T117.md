## Objective

`model_downloader.py` exists with complete download+checksum logic, but `sync_service.py` never imports or calls it. The downloader must be integrated into the sync loop so model files are actually downloaded after model staging.

## Acceptance Criteria

- [ ] After model staging in `sync_models()`, `ModelDownloader.download_models_for_pack(pack_id)` is called
- [ ] Downloaded files appear at `source_downloads/t3k/{model_id}/{filename}`
- [ ] `sync_service.py` imports and instantiates `ModelDownloader`
- [ ] Download failures do not crash the sync loop (logged and continued)

## Test Approach

**CRITICAL: No mocking. No unittest.mock. No AsyncMock. No MagicMock. No patch.**

Tests MUST use `inspect.getsource()` to verify the integration statically:
- Verify `sync_service.py` source contains `ModelDownloader` import
- Verify `sync_models` function source contains `download_models` call
- Verify error handling wraps the download call (try/except or similar)

This is a wiring task — the tests verify the code is connected, not the download behaviour.
The `ModelDownloader` itself already has its own download+checksum logic.

**Location:** `tests/unit/t3k/` (NOT integration — this is static source analysis)
