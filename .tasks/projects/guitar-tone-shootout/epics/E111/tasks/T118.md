## Objective

`GearSyncConsumer._poll_queue()` passes SQLAlchemy params as kwargs (lines 83-88) instead of a dict — this crashes at runtime. The `_dead_letter()` method uses f-string SQL (SQL injection risk). Fix these bugs and verify the full data flow: sync → pgmq → consumer → gear rows in gts_core.

## Acceptance Criteria

- [ ] Fix `_poll_queue`: use `text(...).bindparams()` or dict params for SQLAlchemy `execute()` — no kwargs
- [ ] Fix `_dead_letter`: use parameterised query, not f-string SQL
- [ ] After triggering sync + consumer run: Gear rows exist in `gts_core.gear` table
- [ ] After sync: `GearSource` rows link gear back to T3K source records
- [ ] After model sync: `GearModel` rows exist linked to parent Gear
- [ ] Consumer dead-letters messages with `read_ct > 5`
- [ ] Consumer moves invalid messages (schema validation failure) to dead-letter queue
