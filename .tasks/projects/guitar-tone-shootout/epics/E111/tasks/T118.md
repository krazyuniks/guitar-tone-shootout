## Objective

Write real integration tests for the pgmq consumer and GearMapperService. The implementations exist — tests must verify observable product behaviour using real dual PostgreSQL sessions (gts_core + gts_t3k_source), seeding `GearSyncRecord` objects and verifying DB rows.

## Acceptance Criteria

- [ ] After `mapper.process_pack_sync(record)`, `SELECT count(*) FROM gear` returns 1
- [ ] After pack sync, `GearSource` row exists with correct `(source_name, source_record_id)`
- [ ] After `mapper.process_model_sync(record)`, `GearModel` row exists linked to parent Gear
- [ ] When source_updated_at <= existing, mapper skips update (row unchanged in DB)
- [ ] When source_updated_at > existing, mapper updates Gear fields
- [ ] Consumer reads from real pgmq queue, processes message, archives it
- [ ] Consumer moves invalid messages (schema validation failure) to `sync_dead_letter` queue
- [ ] Consumer moves messages with read_ct > 5 to dead-letter

## Test Approach

- **Location:** `tests/integration/worker/test_gear_sync_consumer.py`
- **DB:** Real PostgreSQL dual sessions (gts_core + gts_t3k_source) in Docker
- **Data:** Create `GearSyncRecord` instances directly (Pydantic dataclass — no mock needed)
- **pgmq:** Real pgmq extension available in PostgreSQL Docker container
- **Mapper tests:** Test `GearMapperService` independently with real sessions

**Testing policy:** No mocking. Tests use real services — real databases, real Redis, real T3K API, real pgmq. The `test_quality_check.py` gate bans all `unittest.mock` imports with zero exceptions.
