## Objective

Write real integration tests for the scheduler tasks (SOURCE_SYNC handler, ensure_source_sync_running, auth refresh). The implementations exist — tests must verify observable product behaviour using real PostgreSQL sessions and real Redis.

## Acceptance Criteria (Observable Product Behaviour)

- [ ] `handle_source_sync` runs real sync with real T3K API, staging rows appear in DB
- [ ] `ensure_source_sync_running` with no Redis lock + T3K_SYNC_ENABLED=true dispatches job
- [ ] `ensure_source_sync_running` with existing Redis lock does NOT dispatch
- [ ] `ensure_source_sync_running` with T3K_SYNC_ENABLED=false does NOT dispatch
- [ ] Auth refresh task updates `oauth_tokens` table in gts_t3k_source via real T3K OAuth refresh

## Test Approach

- **Location:** `tests/integration/worker/test_source_sync_jobs.py`
- **DB:** Real PostgreSQL session in Docker
- **Redis:** Real Redis connection at `redis:6379` in Docker
- **T3K API:** Real T3K API calls using auth tokens from `.gts-auth.json`
- **TaskIQ:** Use `InMemoryBroker` or verify side effects (staging rows in DB, Redis lock state)

**Testing policy:** No mocking. Tests use real services — real databases, real Redis, real T3K API, real pgmq. The `test_quality_check.py` gate bans all `unittest.mock` imports with zero exceptions.
